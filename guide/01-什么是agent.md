# 01 · 什么是 Agent

> 这一章不讲代码。先把三个容易混的东西分开：
> **聊天机器人、工作流、Agent。**
>
> 分清了，后面所有设计选择才有依据。

---

## 一、三个东西，一句话区分

| | 一句话 | 谁决定下一步 | 例子 |
|---|---|---|---|
| **聊天机器人** | 你说一句，它回一句 | 不需要决定 | 客服问答 |
| **工作流** | 按固定步骤走 | 你（代码里写死） | 上传简历 → 解析 → 打分 |
| **Agent** | 自己决定下一步做什么 | **模型** | 订场地（查几个候选不确定） |

**关键区别不在"用不用模型"，在"谁决定路径"。**

聊天机器人也调模型，但路径是"你问我答"，没有分支。
工作流可能调 5 次模型，但每一步都是你写死的。

**只有 Agent 的路径是模型现场决定的。**

---

## 二、一个容易混的判断

很多人以为："步骤数不确定 = 必须用 Agent"。

**不对。**

举个例子：订场地。

- 可能查 3 个候选就够了
- 也可能查 13 个都不合适

**步骤数确实不确定。但动作是可枚举的**：搜索、查档期、查报价、下单。

这种情况**不需要 Agent**——用"循环 + 条件分支"就够了，因为模型不需要发明新动作。

**判断标准**：

```
步骤数不确定，但动作能枚举  →  循环（不是 Agent）
动作本身要看情况决定       →  Agent
```

我们的会务系统就是第一种：五个工具固定，模型只是决定"先查哪个、要不要继续查"。

严格说，它是"**工作流骨架 + 一个 Agent 节点**"——只有"决定调什么工具"那一步交给模型，判定和执行都是代码。

---

## 三、为什么需要 Harness

假设你已经能让模型调工具了。裸跑会出这些事：

| 现象 | 原因 |
|---|---|
| 它一直调同一个工具 | 你忘了把结果回填，它以为没成功 |
| 聊久了变傻 | 上下文太长，模型注意力分散 |
| 它直接下单了，没问人 | 你没设"写操作要审批" |
| 账单突然很高 | 没有步数上限，它跑了 200 步 |
| 出错了查不出原因 | 没记录它看到了什么 |

**这些都不是模型的问题。**

模型只会做一件事：**根据你给的消息，预测下一条消息**。

它不知道"下单要谨慎"，不知道"这个工具挂了应该换一个"，也不知道"你已经花了 3 毛钱"。

**Harness 就是补这些的那一层。**

---

## 四、Harness 里有什么

一个能用的 harness，至少要管五件事：

| 组件 | 管什么 | 不管会怎样 |
|---|---|---|
| **循环** | 什么时候继续、什么时候停 | 跑不完，或者跑过头 |
| **工具** | 模型能做什么、怎么做 | 它可能调不存在的工具，或者传错参数 |
| **上下文** | 模型每次看到什么 | 越聊越贵，最后超窗口 |
| **判定** | 哪些操作要做、哪些要拦 | 它可能花超预算、订错场地 |
| **记录** | 出了事怎么查 | 只能靠"再跑一遍看看" |

这五件事，就是后面第 3-8 章的内容。

---

## 五、一个真实的分层

我们的会务系统分四层：

```
应用层    业务逻辑（订场地、汇总、压缩）
  ↓
编排层    调度、会话、事件（Engine）
  ↓
运行时层  图、状态、中断（LangGraph）
  ↓
模型层    消息、工具调用（LangChain）
```

**为什么要分层**：判断标准是"**加一个功能要改几个文件**"。

- 加一个新工具 → 只改 `tools.py`（1 个文件）
- 加一个新工位 → 改 `tasks.py` + 注册（2 个）
- 换一个模型 → 改 `.env`（0 个）

**如果加一个工具要改 5 个文件，说明分层错了。**

## 六、数据科学背景的人最容易误解的三件事

### 误解一：以为模型有记忆

你在 ChatGPT 里聊得很顺，会以为它记得。

**它不记得。** 是网页每次都把历史重发了。

每问一次，你都要把之前的对话全部重新传一遍——**和"每次调用都要重新传整个 DataFrame"一样**。

### 误解二：以为模型能执行

模型只会**说**"我要调用 search_venues"。

**场地并不会真的被查。** 真正查的是你的代码。

模型是个非常聪明的"分析师"，但它没有手。

### 误解三：以为调 prompt 能解决所有问题

模型答错，第一反应是改 prompt。

但很多问题是结构性的：

| 现象 | 改 prompt 有用吗 |
|---|---|
| 它重复调同一个工具 | ❌ 要改回填逻辑 |
| 它一次调 13 个工具 | ⚠️ 可能有用（告诉它别批量） |
| 它把预算算错 | ❌ 要让代码算，别让它算 |
| 它忘了前面的结论 | ❌ 要改上下文管理 |

**能用代码解决的，不要靠 prompt。**
