## 一、先澄清一个词：State

**State 不是"节点"，也不是"阶段枚举"。**

这是学 LangGraph 最大的坎，因为「状态」有两个意思：

| | 状态机的 state | LangGraph 的 State |
|---|---|---|
| 是什么 | 一个**阶段**（枚举值） | 一份**数据**（字典） |
| 例子 | 「待审批」「已通过」 | `{"count": 2, "log": "ab"}` |
| 有几个 | 有限个，同时只有一个 | 一个，内容一直在变 |

**LangGraph 借了 state 这个词，但指的是后者。**

### 三者各归各

```
         ┌──────────────────────┐
         │   State（草稿纸）     │   ← 数据，在节点之间传来传去
         │   count: int         │
         │   log: str           │
         └──────────────────────┘
                  ↑ 每个节点都读它、写它
                  │
   START ──→ [a] ──→ [b] ──→ END
              ↑       ↑
            节点     节点              ← 这才叫节点
```

```python
# ① 草稿纸的格式（有哪几栏）——不是节点
class State(TypedDict):
    count: int
    log: str

# ② 节点（"a" 是名字，step_a 是干活的函数）
g.add_node("a", step_a)

# ③ 流程（谁接谁）
g.add_edge(START, "a")
g.add_edge("a", "b")
```

## 二、最小可跑的图

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    count: int
    log: str

def step_a(state: State):
    return {"count": state["count"] + 1, "log": state["log"] + "a"}

def step_b(state: State):
    return {"count": state["count"] + 1, "log": state["log"] + "b"}

g = StateGraph(State)
g.add_node("a", step_a)
g.add_node("b", step_b)
g.add_edge(START, "a")
g.add_edge("a", "b")
g.add_edge("b", END)

app = g.compile()
print(app.invoke({"count": 0, "log": ""}))
```

**跑出来是什么**：

```
{'count': 2, 'log': 'ab'}
```

**逐节点看**：

```
初始       count=0, log=""
step_a 读   count=0, log=""
step_a 写   {"count": 1, "log": "a"}
step_b 读   count=1, log="a"
step_b 写   {"count": 2, "log": "ab"}
最终       count=2, log="ab"
```

**注意**：节点函数只返回"要改的字段"，不用返回整张草稿纸。

### 和 sklearn Pipeline 的区别

`Pipeline([("scaler", ...), ("clf", ...)])` 也是一步接一步。

但 Pipeline 只能**一条直线**。图还能做三件它做不到的事：

| 能力 | 例子 | 见哪节 |
|---|---|---|
| 分叉 | 有解走一条路，无解走另一条 | 第四节 |
| 循环 | 查完不满意，回去再查 | 第五节 |
| 暂停 | 下单前停下等人确认 | 第 7 章 |

## 三、覆盖 vs 追加

### 两种写入方式

| 方式 | 效果 | 类比 |
|---|---|---|
| **覆盖** | 只留最新的 | `df["col"] = new` |
| **追加** | 越写越长 | `pd.concat([df, new])` |

**选错了不会报错，只会行为不对。**

### 代码上只差一个标注

```python
# 覆盖
class SheetA(TypedDict):
    log: str

# 追加
class SheetB(TypedDict):
    log: Annotated[List[str], operator.add]
```

**跑一下看区别**（`examples/ch2_langgraph/e02_reducer.py`）：

```
版本 A（覆盖）：
  [A] 写入：A 写了这条
  [B] 写入：B 写了这条
  [C] 写入：C 写了这条
  最终 log = 'C 写了这条'          ← A 和 B 的都没了

版本 B（追加）：
  最终 log = ['A 写了这条', 'B 写了这条', 'C 写了这条']
```

### 一个反直觉的细节

```python
class State(TypedDict):
    log: str                                  # 覆盖

def step_a(state):
    return {"log": state["log"] + "a"}        # 但手动读了旧值

def step_b(state):
    return {"log": state["log"] + "b"}
```

**机制是覆盖，结果却像追加**：

```
初始   log = ""
step_a 读 "" → 拼 "a"  → 写 {"log": "a"}
step_b 读 "a" → 拼 "ab" → 写 {"log": "ab"}
最终   log = "ab"
```

**但如果节点不读旧值呢？**

```python
def step_a(state):
    return {"log": "a"}      # 不读
def step_b(state):
    return {"log": "b"}
```

**跑出来是什么**：

```
{'log': 'b'}      ← A 写的被吃掉了
```

**这就是"覆盖"的真相**：不是"值不会累积"，而是**"你返回什么就是什么，旧值不参与"**。

### 我们踩过的坑

上下文压缩模块里有个字段：

```python
injected: List[str]        # ← 忘了写 Annotated
```

它本该记「已经注入过哪些提醒」，结果每次被覆盖，只剩最后一条。

于是同一条提醒反复注入，模型看烦了也不管用。

**这个 bug 的特点**：

- 不报错
- 单次调用的测试能过
- 只有跑多步才暴露

### 怎么记住

**凡是列表字段，先问：这是「累积的记录」还是「当前的列表」？**

| 场景 | 该用 |
|---|---|
| 对话历史 | 追加 |
| 已下的单 | 追加 |
| 已注入的提醒 | 追加 |
| 当前状态 | 覆盖 |
| 本轮待执行的工具 | 覆盖 |

## 四、条件分支

条件边 = 一个函数，返回"下一步去哪"。

```python
def route(state) -> str:
    if state["n_candidates"] == 0:
        return "none"
    if state["best_price"] > 9000:
        return "expensive"
    return "ok"

g.add_conditional_edges("judge", route, {
    "none": "report_no_solution",
    "expensive": "report_over_budget",
    "ok": "book",
})
```

**跑一下看三条路**（`e03_branch.py`）：

```
一个候选都没有
  [无候选] 一个都没找到，报告无解
  结果：没有符合条件的场地

找到了但太贵
  [超预算] 最便宜 12000，超了
  结果：最低 12000，超出预算

找到了且在预算内
  [可订] 最便宜 8280，可以订
  结果：推荐下单，8280
```

### 一个必踩的坑

**路由返回值对不上分支名。**

```python
return "no_result"      # 但路由表里写的是 "none"
```

**跑出来是什么**：

```
KeyError: 'no_result'
Expected: 'none', 'expensive', 'ok'
```

**关键是：编译时不报，运行时才报。**

```python
app = g.compile()       # ← 能通过
app.invoke(...)         # ← 跑到那个分支才炸
```

**这就是为什么门禁要"真跑一遍"**——光看代码看不出这个错。

## 五、循环

条件边返回"自己"，就是循环。

```python
g.add_conditional_edges("check", after_check, {
    "again": "check",      # ← 回到自己
    "done": END,
})
```

**跑一下**（`e04_loop.py`）：

```
[第 1 圈] 查 V01 … 满档
[第 2 圈] 查 V02 … 满档
[第 3 圈] 查 V03 … 有空档！
找到：V03，转了 3 圈
查过：['V01', 'V02', 'V03']
```

### 退出条件是关键

```python
def after_check(state):
    if state.get("found"):
        return "done"        # 找到了
    if not state.get("queue"):
        return "done"        # 没得查了
    return "again"
```

**忘了第一个判断**，会一直查到队尾。**两个都忘**，就是死循环（靠 `recursion_limit` 兜底）。

## 六、我们的五节点图

把上面这些拼起来：

```
        ┌──────────────────────────┐
        ↓                          │
   [agent] ──→ [judge] ──→ [execute] ──┘
        │           │
        │           └──→ [approve] ──→ [execute]
        │
        └──→ [finalize] ──→ END
```

| 节点 | 干什么 | 为什么单独拆出来 |
|---|---|---|
| `agent` | 问模型 | — |
| `judge` | 判定工具能不能用 | **纯判定，可以随便重跑** |
| `approve` | 停下来等人批 | 有 interrupt |
| `execute` | 真正执行工具 | **有副作用，前面不能有 interrupt** |
| `finalize` | 收尾 | — |

**最关键的设计**：`judge` 和 `execute` 分开。

三个理由：

1. **副作用边界**——只有 execute 改世界
2. **中断边界**——approve 里没有副作用，重跑安全
3. **测试边界**——可以单独测判定逻辑，不用真的下单

**日志长这样**：

```
step 1  agent    → 要调 search_venues
        judge    → allow
        execute  → 13 个候选
step 2  agent    → 要调 get_availability × 13
        judge    → allow × 13
        execute  → 8 个 AVAILABLE
step 3  agent    → 要调 create_booking(V01)
        judge    → prompt（占预算 92%）
        approve  → 【中断，等人】
        （用户确认）
        approve  → approved=True（重跑一次，无副作用）
        execute  → BK001
step 4  agent    → 最终答复
        finalize → turn.completed
```

## 小结

| 问题 | 答案 |
|---|---|
| State 是什么 | 数据（草稿纸），不是节点也不是枚举 |
| 三个词各归各 | State=数据、node=步骤、edge=流程 |
| 覆盖和追加怎么分 | 看是不是 `Annotated + operator.add` |
| 覆盖的真相 | 你返回什么就是什么，旧值不参与 |
| 条件边最坑的地方 | 返回值对不上分支名，编译时不报 |
| judge 和 execute 为什么要拆 | 副作用 / 中断 / 测试三个边界 |
