## 阶段一：能问一句（30 分钟）

### 目标

```
用户说话 → 模型回话
```

### 要做的

```python
from langchain_core.messages import HumanMessage, SystemMessage

messages = [
    SystemMessage(content="你是会务助手。"),
    HumanMessage(content="订个 50 人的场地"),
]
reply = model.invoke(messages)
print(reply.content)
```

### 这时候你会遇到

| 现象 | 原因 | 看哪章 |
|---|---|---|
| 它说"我要查场地"但没查 | 正常，模型只会说 | 03 |
| 换个说法它就不认识了 | 没有 system prompt | 02 |

### 验收

能跑通，并且**意识到"它没真查"**。

## 阶段二：能调一个工具（1 小时）

### 目标

```
用户说话 → 模型说要查 → 你查 → 告诉它 → 它给结论
```

### 要做的

```python
def search_venues(city: str, min_capacity: int) -> str:
    """按城市和人数搜场地。"""
    return json.dumps([{"venue_id": "V01", "capacity": 60}])

# 三步
reply = model.invoke(messages)
messages.append(reply)                       # ①
for call in reply.tool_calls:                # ②
    result = search_venues(**call["args"])
    messages.append(ToolMessage(
        content=result,
        tool_call_id=call["id"],             # 取餐号
    ))
final = model.invoke(messages)               # ③
```

### 这时候你会遇到

| 现象 | 原因 |
|---|---|
| 它重复调同一个工具 | 忘了 `messages.append(reply)` |
| 报错说找不到 tool_call_id | 取餐号对不上 |
| 它说"查到了"但内容是空的 | 工具返回了空 |

### 验收

能完整跑通三步，并且**能解释"为什么必须 append 模型那句话"**。

**参照**：`examples/ch1_langchain/e02_tool.py`

## 阶段三：能循环（1 小时）

### 目标

```
上面那件事重复做，直到它说"完事了"
```

### 要做的

```python
for step in range(MAX_STEPS):
    ai = model.invoke(messages)
    messages.append(ai)

    if not ai.tool_calls:
        break

    for call in ai.tool_calls:
        try:
            body = str(tool_map[call["name"]].invoke(call["args"]))
            ok = True
        except Exception as e:
            ok = False
            body = json.dumps({"error": str(e), "hint": "换个方式试试"})

        messages.append(ToolMessage(
            content=body, tool_call_id=call["id"],
            status="ok" if ok else "error",
        ))
```

### 两个必须加的东西

| 加什么 | 不加会怎样 |
|---|---|
| `MAX_STEPS` | 可能跑 200 步 |
| 工具 try/except | 一个工具挂了整轮崩 |

### 验收

能跑多步任务，并且**故意让一个工具失败，看模型能不能自己调整**。

## 阶段四：能停下来（2 小时）

### 目标

```
下单前停下来问人
```

### 要做的

**关键：先把「判定」和「执行」拆开。**

```python
def judge_node(state):
    """只判定，不改世界。"""
    for call in state["pending"]:
        verdict = policy.check(call["name"], call["args"])
        if verdict.action == "forbid":
            return {"blocked": [...]}
        if verdict.action == "prompt":
            return {"need_approval": [...]}
    return {"pending": state["pending"]}

def approve_node(state):
    """停下来等人。这里没有副作用。"""
    answer = interrupt({"question": "确认下单？", "args": ...})
    return {"approved": answer}

def execute_node(state):
    """真正执行。前面不能有 interrupt。"""
    if not state.get("approved"):
        return {"pending": []}
    for p in state["pending"]:
        tool_map[p["name"]].invoke(p["args"])
```

### 三个必须记住的

| 记住什么 | 为什么 |
|---|---|
| `compile(checkpointer=...)` 必须给 | 不给会静默失效 |
| interrupt 之前不能有副作用 | 恢复时会重跑 |
| 幂等表绑定业务对象 | 全局变量会跨用例污染 |

### 验收

能中断、能恢复，并且**故意在 interrupt 前加一个副作用，看它执行两次**。

**参照**：`examples/ch2_langgraph/e05_pause.py`

## 阶段五：能管上下文（2 小时）

### 目标

```
长任务不爆窗口，且不丢决策依据
```

### 要做的

```python
def agent_node(state):
    used = estimate_tokens(state["messages"])

    # ① 超阈值 → 折叠成事实表
    if used > LIMIT * 0.85:
        msgs, facts = compact_messages(state["messages"])

    # ② 还是高 → 注入提醒
    if used > LIMIT * 0.75:
        extra.append("你的预算不多了，请收尾")

    # ③ 发请求
    ai = model.invoke(msgs + extra)
```

### 折叠函数的两个关键

| 关键 | 为什么 |
|---|---|
| 保留**结论**（价格、状态），不是原始 JSON | 模型要能比较 |
| 能合并**已有的**事实表 | 反复压缩会丢结论 |

### 不要做的事

**不要用"遮蔽"**（把旧工具输出全删）。

我们实测：遮蔽后 C01/C10 全部从"正确"变成"放弃任务"——因为模型没法比较候选了。

**前提不同**：SWE-bench 里文件能重读，我们的任务要跨历史汇总。

### 验收

跑一个长任务，看峰值 token 有没有被压到上限内，**且决策没变**。

## 阶段六：能验证（半天）

### 目标

```
知道它到底对不对
```

### 要做的顺序

**① 先写确定性断言，不要碰 judge**

```python
def evaluate(case, world, messages):
    bookings = world.list_bookings()
    if case.expected is None:
        return {"success": len(bookings) == 0}      # 该拒绝
    return {
        "success": (len(bookings) == 1
                    and bookings[0]["venue_id"] == case.expected["venue_id"])
    }
```

**② 造 10-20 个用例，从真实失败里来**

| 用例类型 | 例子 |
|---|---|
| 标准路径 | 有解，预算充足 |
| 边界 | 刚好在预算边缘 |
| 无解 | 全满档 |
| 长轨迹 | 13 个候选 |
| **工具失败** | 故意让一个工具抛异常 |

**③ 跑 pass^k，不只 pass@1**

```bash
python -m run_real --repeat 3
```

**④ 加门禁**

```python
def run_gate():
    ...
    if report.passed:
        return 0
    return 1        # ← 这个 1 才是门禁的意义
```

### 最重要的一条

> **每加一个检查项，问自己：我把对应代码改坏，这项会不会变红？**

不会 → 装饰品。

**我们踩过三次**：门禁指标从未触发、被别的路径兜住、把"没做"算成"做对"。

### 验收

故意改坏三处，**三处都能被门禁拦住**。

## 一个反直觉的收尾

这套东西里最值钱的，不是"能跑"，是**每个选择都能说清代价**。

比如：

| 选择 | 代价 |
|---|---|
| 用 ReAct 而不是 Plan-Execute | 成本高，但每步能看情况 |
| 用折叠而不是遮蔽 | 要写折叠逻辑，但决策依据不丢 |
| 门禁只跑 3 个用例 | 快，但会漏组合 bug |
| 用 InMemorySaver | 简单，但重启丢状态 |

**没有"更好的选择"，只有"代价你接不接受"。**
