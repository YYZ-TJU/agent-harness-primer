## 一、先答 thread

这个词在这套系统里有**两个完全不同的意思**，混着看会晕。

### 意思一：thread_id —— 会话编号（最常出现）

**是什么**：一串随机字符，比如 `t1`、`x`、`a3f9c2b1`。

**干什么**：标记「这是哪一场对话」。

**拿什么比**：**微信里的聊天窗口**。

- 你跟 A 聊天的窗口，和跟 B 聊天的窗口，消息不串
- 微信怎么知道该显示哪条？靠窗口编号
- `thread_id` 就是这个编号

**在这套系统里**：

```
thread_id = "t1"   → 第一场对话（比如订场地）
thread_id = "t2"   → 第二场对话（另一件事）
```

两场对话的历史、草稿、订单，各存各的，互不影响。

**实际用法**：

```python
engine.submit(工单, "t1")     # 投给 t1 这个窗口
engine.submit(工单, "t2")     # 投给 t2
```

**为什么重要**：你查「上周三那次为什么失败」，只要知道当时的 `thread_id`，就能把那场对话的全部记录调出来。

### 意思二：Thread —— 执行线程

**是什么**：程序里的一条"并行跑道"。

**干什么**：让程序同时做两件事。

**拿什么比**：**一个人长了第三只手**。

正常程序是一件事做完再做下一件（一只手）。有线程之后，可以一只手打字、另一只手按开关——两件事"同时"在推进。

**在这套系统里只出现一次**：

```python
import threading
self._cancel_event = threading.Event()
```

这是「取消信号」的载体。

**为什么需要它**：

用户点取消的时候，可能程序正在跑（比如正在调模型）。要让它随时能收到"别跑了"这个信号，就得有一个不依赖主流程的通道。

`threading.Event` 就是这个通道——像**门口挂的一盏灯**。
- 主流程在屋里干活
- 你按了取消 → 灯亮
- 主流程每次走到门口都抬头看一眼灯

**注意**：这个 Thread 和上面的 thread_id **一点关系都没有**。
只是名字碰巧一样——LangGraph 借用了操作系统的「线程」来给「会话」命名。

### 一句话区分

| 写法 | 是什么 | 比作 |
|---|---|---|
| `thread_id`（小写、带 id） | 会话编号 | 微信聊天窗口 |
| `Thread`（大写、或 `threading`） | 并行跑道 | 多长一只手 |

**你看到「thread」时，99% 指的是会话编号。**

## 二、会话相关的词

### session（会话）

**是什么**：一场对话的全部状态——配置、已经跑过几轮、有没有卡在等审批。

**干什么**：管「这一场对话的账」。

**比作**：**一个文件夹**。

- `thread_id` 是文件夹上的编号贴纸
- `session` 是文件夹本身（里面装着配置、历史、当前进度）

**在这套系统里**：

```python
class Session:
    thread_id: str              # 编号
    config: SessionConfig       # 设置（用哪个模型、最多几步）
    turns: List[TurnRecord]     # 跑过几轮，每轮多久
    inbox: list                 # 还没处理的工单
    paused: bool                # 是不是卡在等审批
```

**一句话**：`thread_id` 是名字，`session` 是东西。

### turn（一轮）

**是什么**：你提一个需求 → 系统干完 → 给你答复。这一整个过程叫一轮。

**干什么**：把「一次完整交互」切开，方便算账、方便中断。

**比作**：**一次点餐**。

- 你说"我要一份牛肉面" → 厨房做 → 端上来
- 这是一轮
- 你说"再加个蛋" → 又是新的一轮

**在这套系统里**：每轮有独立编号（`turn_id`）、起止时间、用了多少步、调了几次工具。

### step（一步）

**是什么**：一轮里面的一个小动作。通常是「问一次模型」或「执行一次工具」。

**干什么**：细粒度地记录进度、控制上限。

**比作**：**做菜的一道工序**。

- 一轮"做牛肉面"包含：烧水 → 下面 → 切牛肉 → 装碗
- 每一步做完，可以停下来检查

**在这套系统里**：

```
第 1 步：问模型 → 它说"查一下场地"
第 2 步：执行查询 → 拿到 13 个候选
第 3 步：问模型 → 它说"查档期"
...
```

`MAX_STEPS = 30` 的意思是：**这一轮最多允许走 30 步**，防止它没完没了。

## 三、数据相关的词

### state（状态）

**是什么**：当前这一轮的所有已知信息，存在一个字典里。

**干什么**：让不同的处理环节能读到同一份数据。

**比作**：**一张草稿纸**。

- 你写一条，我写一条
- 下一个接手的人看这张纸就知道进展
- 写错了可以擦掉重写

**在这套系统里**，草稿纸上记着：

```
messages   对话记录
task       任务要求（哪天、多少人、多少预算）
step       走到第几步
pending    这次准备执行的工具
blocked    被拦下的工具
bookings   已经下了几单
```

**为什么重要**：中断之后要恢复，靠的就是这张草稿纸（存在 checkpointer 里）。

### message（消息）

**是什么**：对话里的一条记录。

**干什么**：模型只能通过消息了解"之前发生了什么"。

**比作**：**聊天记录里的一条**。

四种角色：

| 类型 | 谁说的 | 例子 |
|---|---|---|
| `SystemMessage` | 系统设定 | 「你是会务助手，只订上海的场地」 |
| `HumanMessage` | 用户 | 「订个 50 人的场地」 |
| `AIMessage` | 模型 | 「我先查一下有哪些场地」 |
| `ToolMessage` | 工具（不是模型） | `{"venue_id": "V01", "status": "AVAILABLE"}` |

**最后一种最容易误解**：`ToolMessage` 不是模型说的，是**你把工具结果塞回给模型**。

模型本身不能执行任何操作——它只会说"我想调用 XX 工具"。真正去查、去下单的，是我们的代码。

### context / context window（上下文 / 上下文窗口）

**是什么**：模型一次能"看到"的全部内容。

**干什么**：决定它能不能记住前面的信息。

**比作**：**短期记忆的容量**。

- 人一次能记住 7 个电话号码，多了就忘
- 模型一次能处理 N 个字，超了就装不下

`context window = 128K` 意思是：**一次最多能处理 12.8 万个字（约 200 页纸）**。

**注意**：这是「一次」的容量，不是「总共」。每问一次，都要把之前的对话重新塞一遍。

### token（词元）

**是什么**：模型计量的最小单位。一个汉字大约 1 个字 = 1~2 token，英文一个词约 1 token。

**干什么**：算钱、算容量。

**比作**：**手机流量**。

- 你说"我用了 500MB"，不会说"我传了 3 个视频"
- 模型说"这次用了 8000 token"，不会说"我读了 5 页纸"

**为什么重要**：token 直接等于钱。这套系统里一次订场地的任务大约花 25000 token，DeepSeek 上约 3 分钱。

## 四、工具相关的词

### tool（工具）

**是什么**：一段能干实事的代码。查场地、查档期、下单，都是工具。

**干什么**：让模型"能动手"，而不只是"能说话"。

**比作**：**给模型配的一套工具**（螺丝刀、扳手）。

模型自己拧不了螺丝，但它可以说"我要用十字螺丝刀"——然后由我们递过去。

**在这套系统里有 5 个**：

| 工具 | 干什么 |
|---|---|
| `search_venues` | 按城市和人数搜场地 |
| `get_availability` | 查某天有没有空 |
| `get_quote` | 查报价 |
| `create_booking` | 下单 |
| `list_my_bookings` | 看已下的单 |

### tool_call（工具调用 / 调用请求）

**是什么**：模型说"我想用某个工具，参数是这些"。

**干什么**：把模型的意图变成结构化的请求。

**比作**：**点菜**。

```json
{"name": "get_quote", "args": {"venue_id": "V01", "hours": 4}}
```

意思是：「我要用 `get_quote` 这个工具，查 V01，租 4 小时。」

**关键**：模型只是"点了菜"，菜还没做。**真正去做的是我们的代码。**

### tool_result（工具结果）

**是什么**：工具执行完，返回的内容。

**干什么**：让模型知道刚才那步的结果，好决定下一步。

**比作**：**菜端上来了**。

```json
{"venue_id": "V01", "total": 8280}
```

### tool_call_id（调用编号）

**是什么**：每个 `tool_call` 自带的一串编号。

**干什么**：把「请求」和「结果」对上号。

**比作**：**取餐号**。

- 你点了 3 个菜，拿到 3 个号
- 端上来的时候要能对上：A3 号是牛肉面，A4 号是小菜
- 如果对错了，就是你点了牛肉面却拿到炒饭

**这就是为什么前面说「重试不能让模型再调一次」**——同一个取餐号只能对应一份菜，出两份就乱了。

## 五、图相关的词

### StateGraph（状态图）

**是什么**：LangGraph 提供的一种"流程图"写法。

**干什么**：把「先做什么、再做什么、什么情况下跳哪」画出来，让程序照着跑。

**比作**：**地铁线路图**。

- 有站点（节点）
- 有轨道（边）
- 有的站要换乘（条件边）

**为什么用它**：比一堆 `if/else` 更容易看清、更容易改。

### node（节点）

**是什么**：图上的一个站点，对应一段处理逻辑。

**干什么**：做一件具体的事。

**比作**：**一站地铁**。

**我们的五个节点**：

| 节点 | 干什么 | 比作 |
|---|---|---|
| `agent` | 问模型 | 大脑 |
| `judge` | 判定工具能不能用 | 安检 |
| `approve` | 停下来等人批 | 闸机 |
| `execute` | 真正执行工具 | 施工队 |
| `finalize` | 收尾 | 出站 |

### edge（边）

**是什么**：节点之间的连线，表示"下一步去哪"。

**干什么**：控制流程走向。

**两种**：

| 类型 | 意思 | 比作 |
|---|---|---|
| 普通边 | 做完 A 一定去 B | 单行道 |
| **条件边** | 看情况，可能去 B 也可能去 C | 岔路口 |

**条件边最容易出错**：如果漏写了某个情况（比如「模型直接给了答复」这种情况），程序会当场报错。

### reducer（合并规则）

**是什么**：一条规则，说明「新数据来了，跟旧的怎么合」。

**干什么**：决定是"追加"还是"覆盖"。

**比作**：**记账方式**。

- 「追加」= 流水账，每笔都记，越记越长
- 「覆盖」= 余额，只留最新数字

**举个真实例子**：

```python
messages: Annotated[List, add_messages]   # 追加——对话记录只增不减
bookings: Annotated[List, operator.add]   # 追加——每下一单就加一条
status: str                               # 覆盖——只留最新状态
```

**这个写错了不会报错，只会行为不对。** 我们踩过：本该追加的写成了覆盖，结果历史只剩最后一条。

### checkpointer（存档器）

**是什么**：一个组件，定期把"草稿纸"（state）存下来。

**干什么**：让程序中断后能从上次的位置继续。

**比作**：**游戏存档**。

- 你打到第 3 关，存个档
- 关机再开，从第 3 关继续，不用重打

**在这套系统里**：

- 每走一步存一次
- 停在"等审批"时，状态是能恢复的
- 恢复时用同一个 `thread_id` 就能找回

**关键限制**：它存的是「对话进度」，**不存「订单」**。
订单在业务系统里，checkpointer 管不着——这就是为什么"快照能回退、世界不能"。

## 六、流程相关的词

### invoke（一次性调用）

**是什么**：发一个请求，等它全部跑完，一次性拿到结果。

**干什么**：简单场景用。

**比作**：**打电话点外卖**——你等着，对方说完地址、确认菜单、报总价，然后挂断。中间你听不到别的。

**问题**：跑一个 18 步的任务要 20 秒，这 20 秒里你什么都看不到。

### stream（流式）

**是什么**：边跑边往外送消息。

**干什么**：让你能看到"正在做什么"。

**比作**：**看着厨师做菜**——不是等端上来才知道，而是能看到他先洗菜、再切肉。

**在这套系统里**：

```python
for 事件 in engine.submit(工单):
    显示(事件)
```

每发生一件事，就往外送一条。前端就能实时显示进度。

**这就是「流式与事件」那篇讲的东西**——`stream` 是管道，`事件` 是管道里流的东西。

### interrupt（中断 / 暂停等确认）

**是什么**：程序主动停下来，等人做决定。

**干什么**：在关键操作（比如花钱下单）前，让人确认一次。

**比作**：**银行转账的大额确认弹窗**。

- 你点了"转账 5 万"
- 银行不直接转，弹一个窗："确认转给张三 5 万？"
- 你点确认，才真的转

**和"取消"的区别**：

| | interrupt | 取消 |
|---|---|---|
| 谁发起 | 程序自己停 | 用户主动喊停 |
| 停下之后 | 等人答复，然后**继续** | 不再继续 |
| 比作 | 银行弹窗确认 | 你按了急停按钮 |

### resume（恢复）

**是什么**：给暂停的程序一个答复，让它继续跑。

**干什么**：把"等审批"变成"批了/拒了"。

**比作**：**在弹窗上点"确认"**。

**为什么需要它**：`interrupt` 停下来之后，程序不是"挂着"，而是"存了档退出"。要恢复必须重新进入，从存档点继续。

## 七、我们自己的概念

### Engine（引擎）

**是什么**：整个系统的主体，管调度、管会话、管事件。

**干什么**：接收工单 → 派活 → 收集事件。

**比作**：**餐厅的调度台**。

- 客人点单（工单）
- 调度台决定给哪个厨房（哪个工位）
- 做完了端出去（事件流）

### Harness（外挂框架 / 骨架）

**是什么**：套在模型外面的一整套"安全措施 + 记录 + 调度"。

**干什么**：让模型能可靠地干活，而不是裸奔。

**比作**：**攀岩的安全带**。

- 攀岩的人（模型）能力很强，但会失手
- 安全带（harness）不让他摔死

**这个词的来源**：原意是"马具"——套在马身上，让马能拉车而不乱跑。软件里借用来指"套在核心外面的一层控制结构"。

### Op（工单）

**是什么**：一条"要干什么"的指令，是个小数据包。

**干什么**：前端不直接调函数，而是"投一张工单"。

**比作**：**餐厅的点菜单**。

```
Op.user_turn("订个 50 人的场地", date="2026-11-06", budget_cap=9000)
Op.approve(True)        # 批准
Op.interrupt()          # 叫停
```

**为什么不直接调函数**：因为要能排队、能取消、能记录。函数调用做不到这些。

### verdict（判定）

**是什么**：策略层对「这个工具能不能用」的结论。

**干什么**：拦截不该做的操作。

**比作**：**安检的结论**。

三种：

| verdict | 意思 | 比作 |
|---|---|---|
| `allow` | 直接放行 | 安检通过 |
| `prompt` | 要人确认 | 开箱检查 |
| `forbid` | 不许 | 拦下 |

**每条判定都带 `rule`（哪条规则）和 `why`（为什么）**——这样事后能查，模型也能知道自己错在哪。

### gate（门禁）

**是什么**：一道自动检查，不过就不许提交代码。

**干什么**：防止改坏了没人发现。

**比作**：**机场安检门**。

- 你走过去，响了就拦下
- 不响就放行

**关键**：门禁必须能"响"。我们踩过——有个检查项从来没触发过，等于摆设。

### hook（钩子）

**是什么**：在固定时机自动执行的一段代码。

**干什么**：不修改主流程，就能插手做点事。

**比作**：**门口的感应灯**。

- 你不用专门去开灯
- 有人经过（事件发生），它自己亮

**我们的用法**：每轮开始/结束、每次工具调用，都可以挂钩子做记录或告警。

## 八、评测相关的词

### eval / evaluation（评估）

**是什么**：用一批标准用例跑一遍，看对多少个。

**干什么**：知道改完是变好还是变坏。

**比作**：**考试**。

- 题目是固定的（用例集）
- 跑一遍看分数
- 改完再跑，分数涨了就是改对了

### golden set（标准答案集 / 黄金集）

**是什么**：一批"题目 + 标准答案"。

**干什么**：当尺子用。

**比作**：**参考答案**。

**我们的 10 个用例**：C01-C10，每个都有明确的标准答案（该订哪个场地、还是该拒绝）。

### LLM-as-judge（用模型当裁判）

**是什么**：让另一个模型来打分。

**干什么**：有些东西没法用代码判断（比如"这段解释清楚吗"），只能让模型评。

**比作**：**请另一个老师批卷**。

**风险**：这个老师有偏见——偏爱长答案、偏爱自己风格的答案、偏爱排在前面的答案。

**所以我们尽量不用它**，能用代码判断的都用代码。

### pass@k / pass^k（通过率）

**是什么**：两个容易混的指标。

**干什么**：衡量"能不能做"和"稳不稳"。

**比作**：

- `pass@k` = **考 5 次，有一次及格就算过** → 说明"有能力"
- `pass^k` = **考 5 次，每次都得及格** → 说明"靠得住"

**数字差距很大**：单次 80% 成功率，考 3 次全过的概率只有 **51%**，考 8 次只有 **17%**。

### kappa（一致性系数）

**是什么**：一个 0 到 1 的数字，衡量"裁判的判断和人的判断有多一致"。

**干什么**：判断这个裁判能不能信。

**比作**：**裁判的靠谱程度**。

| kappa | 意思 |
|---|---|
| < 0.4 | 这个裁判不能信 |
| 0.4-0.6 | 只能看大趋势 |
| **> 0.6** | 可以用来做门禁 |
| > 0.8 | 几乎和人一样准 |

**为什么不用"准确率"**：因为题目大多是"通过"，裁判只要一直说"通过"就能拿 88% 准确率——但 kappa 会暴露它其实什么都没判断。

## 九、能力扩展与多主体

### MCP

**是什么**：Model Context Protocol，一个让"工具提供方"和"agent 使用方"解耦的协议。

**干什么**：把 M 个 agent × N 个数据源的适配代码，从 M×N 份变成 M+N 份。

**比作**：**USB 接口**。没有 USB，每个设备一种接口；有了 USB，电脑只要一个口。

### RAG

**是什么**：Retrieval-Augmented Generation，检索增强生成。

**干什么**：每次把相关的几段文档喂给模型，而不是指望它记住。

**比作**：**开卷考试**。不用背下来，考的时候翻到那一页。

### embedding

**是什么**：把一段文字变成一串数字（向量），让"意思相近"变成"距离相近"。

**干什么**：RAG 检索的基础——问题向量和文档向量比距离。

**比作**：**把每句话放到一张地图上的某个坐标**。意思像的靠得近，检索就是"找附近有什么"。

### chunk

**是什么**：把长文档切成的片段（通常几百字）。

**干什么**：检索的单位是 chunk，不是整篇文档。

**比作**：**把一本书撕成一页页**。你查资料时抽几页，不会抱整本。

### Memory

**是什么**：跨会话保留的信息——用户偏好、历史决策、踩过的坑。

**干什么**：让 agent 下次见到同一个用户时"记得"上次的事。

**比作**：**备忘录**。和聊天记录不同——备忘录只记要点，聊天记录是全量。

### Skill

**是什么**：打包好的"怎么做某件事"——步骤、检查点、常见错误。

**干什么**：让 agent 照着做，而不是每次现推。

**比作**：**菜谱**。工具是锅铲，Skill 是"这道菜先炒什么后放什么"。

**和工具的区别**：**工具给手，Skill 给方法。**

### Handoff

**是什么**：任务交接——把活交给另一个 agent，或者交给人。

**干什么**：处理"超出能力或权限"的任务。

**比作**：**转诊**。社区医院看不了，写一张转诊单给三甲——单子上要写清症状、已做的检查、怀疑什么。

### Trajectory

**是什么**：一次任务的全部决策记录，包括模型每一步看到的完整输入。

**干什么**：事后查"它为什么这么决定"，以及回放。

**比作**：**行车记录仪**。出事时不只能看到"撞了"，还能看到撞之前那 10 秒发生了什么。

**和普通日志的区别**：日志记"调用了什么"，轨迹记"当时看到了什么"。

---

### Ontology

**是什么**：对"业务里有哪些东西、它们怎么关联、有什么规则"的正式定义。

**干什么**：让 agent 不靠猜——知道"场地属于展馆""订单必须挂一个场地"。

**比作**：**业务世界观**。不是数据表，是"这个世界有哪些东西、它们怎么相处"。

**和 RAG 的区别**：RAG 让 agent 读到答案，本体让 agent 不会读错。

### OWL

**是什么**：Web Ontology Language，W3C 的本体建模语言。

**干什么**：定义类、属性、层级关系（"展馆包含场地"）。

**比作**：**建筑图纸**。规定有哪些房间、怎么连通。

**一个关键限制**：OWL 是**开世界**语义——图里没提到"审批"，不能推出"没有审批"。所以它**不能当运行时验证器**。

### SHACL

**是什么**：Shapes Constraint Language，W3C 的数据验证语言。

**干什么**：定义"一条合法数据必须满足什么"（订单必须有审批）。

**比作**：**安检门**。过不了就是过不了，没有"可能还有别的地方"。

**和 OWL 的分工**：OWL 管"是什么"，SHACL 管"合不合格"。

### SPARQL

**是什么**：RDF 图的查询语言。

**干什么**：像 SQL 查表一样查关系（"这个订单的场地属于哪个展馆"）。

**比作**：**关系版的 SQL**。SQL 查行和列，SPARQL 查点（实体）和边（关系）。

### 语义层

**是什么**：把"指标怎么算"定义一次，处处复用。

**干什么**：保证三个 agent 说的"营收"是同一个数。

**比作**：**统一的度量衡**。不管谁量、用什么尺，一米的长度是固定的。

**和 Ontology 的区别**：语义层回答"多少钱"，本体回答"这是什么、能做什么"。
